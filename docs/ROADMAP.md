## 原則

- **データ駆動設計** — TSV/INIによる値管理を徹底し、マジックナンバーは用いない
- **データ指向設計（ECS）** — メモリレイアウト・実行効率を重視した設計を志向する
- オブジェクト指向的要素（状態を持つシステム、コアオブジェクトなど）を完全には排除していないが、可能な限り減らす方針
- config vs table の判断基準: config = カテゴリ共通のデフォルト値、table = エンティティごとのoverride
- Engine/Gameレイヤーの分離を維持
- 各Phaseのチェックポイントは締め切りではなく、**ペース確認用の指標**として使う
